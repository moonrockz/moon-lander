Object JSON properties design

Approved #112 contract. See proposal, requirements and tasks.

Context

Schema version 1 writes ordered property entries. Morphir needs named lookup and complete duplicate evidence through public sinks.

Decisions

Owner: named properties and exact duplicate contract

The last occurrence wins. Every repeated name has all values in original per-name order, including the winner, under duplicateProperties. Unique names do not appear in history. Omit the history object without repeats. Preserve JSON types and metadata isolation.

Call: additive formatter and schema version 2

Keep format_json_line unchanged. Add format_json_object_line. Both call one private renderer for common metadata and safe JSON value encoding. Schema version 1 remains byte compatible. Version 2 identifies the properties object and optional history.

Call: typed sink policy

Add JsonProperties with OrderedArray and NamedObject cases in the pure formatting package. FileSink::new accepts json_properties with OrderedArray as its default and exposes a getter. It affects JsonLines only. Text stays unchanged. File ownership remains based on directory, stem and extension, so two policies cannot open the same set together.

Call: group values without mutating events

Walk the captured ordered list once, keeping the last value and per-name arrays. Emit only arrays with two or more values as history. Use the existing safe JSON writer for nested values, escaping and non-finite numbers. State stays local to one render.

Verification and risks

Four-target formatter tests check interleaved names, a null winner, unique arrays, nested objects, escapes, empty events and byte-compatible defaults. Public native, Node and Bun rolling sessions write both formats, roll and drain, and an independent parser checks their files. Registry fixtures exercise the additive API. A new schema version prevents an old array reader from treating the object as its schema.

Migration

Existing callers need no changes. Consumers select NamedObject on a JsonLines FileSink or call format_json_object_line. This adds no production I/O or dependencies. Land reviewed code after green CI and publish through the authorized release workflow.
