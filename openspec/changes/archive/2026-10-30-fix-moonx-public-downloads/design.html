Context

See the proposal for the failure. The source ZIP, Wasm asset and checksum sidecar use the same public registry host. Its normal response redirects to a CDN. The pinned async HTTP client sends one request.

Goals and non-goals

Keep the public URL as the entry point and follow its redirects before checking the response bytes. Keep this repair in the unpublished checker. Do not change the launcher, published files, versions, signal contract or runtime.

Decisions

HTTP-1. Call: one bounded download boundary

Use canonical async HTTP for all three downloads. Follow 301, 302, 303, 307 and 308 Location responses, with a limit of eight redirects. Require a final 200 response. Missing Location, other response codes and an exhausted limit fail with typed download errors. The registry supplies absolute CDN URLs. Do not pin its current CDN hostname or replace the default registry.

Keeping three one-request calls fails on the real registry. A hard-coded CDN URL bypasses the public entry point. An external downloader adds a tool prerequisite. The shared async boundary avoids those alternatives.

HASH-1. Call: preserve approval identity

Use the default download.mooncakes.io/prebuild/ asset endpoint from the pinned stock registry client. Read the first whitespace-delimited checksum token from its SHA256SUM sidecar and normalize its hex case, as that client does. A sidecar filename is not an authority for the downloaded URL.

Return exact response bytes. Check the source ZIP against the original workflow-approved digest before extraction. Parse the downloaded sidecar and check the Wasm asset and cold Moonx cache against it. Never infer an approval digest from the public archive.

REL-1. Owner: workflow-only release recovery

The existing owner authorization covers publication of 0.9.0 through the Release workflow. All eleven modules are already uploaded. The follow-up must keep their files unchanged and prove the new approval map equals artifact 13023517211 from run 41148930827. Use a fresh workflow run after the reviewed fix merges. Keep the separate public-proof gate open until it passes.

macOS and Linux package ZIP entry order differs. Compare local package hashes with the pre-fix local baseline and verify published package files have no source changes. Require Linux CI's actual archive map to equal the original approval before merge and promotion. Local repack bytes do not replace that approval.

If verification fails, keep release promotion blocked.
