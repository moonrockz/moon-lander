Context

See proposal.md for the motivation and the docs-site delta for the contract. The current apps/site implements content discovery, rendering, API metadata, search, browser islands, link checks and version assembly. Its landing fragment has stale installation text, including a fixed 0.6.0 version and module count.

Telescope 0.5.1 is the published release selected for this change. It provides the same core static-site model, the Smithy palette, optional header and favicon paths, native host operations, and explicit consumer fence providers. Optional gallery and editor feature adoption remains outside this design. The current Moon-Lander compiler pin differs from Telescope's qualified patch, so the first story must prove public-package compatibility with real API metadata before the old generator is removed.

Goals and non-goals

Use one shared site engine. Keep Moon-Lander-specific content, diagram adapters, source policy, release discovery and acceptance tests in this repository. The published framework must retain its existing dependency graph. No generic site code is copied from Telescope.

No new playground, tutorial engine, gallery, web service, analytics, external font loading, framework API change or release is included. Existing historical site archives keep their own bytes.

Landing page direction

This offline mockup sets the layout and palette. It is a design preview, not a working site. The large mascot balances the headline. Smithy's indigo remains the UI accent; gold stays in the lander artwork. The actual page also links the mediator, actors and the other package guides.

Decisions

SITE-1. Owner: use Telescope and the Smithy visual family

The user selected Telescope, a Smithy-like landing page and matching colors. Use the published moonrockz/telescope@0.5.1 package. Do not consume a sibling worktree or unpublished candidate. Keeping the present engine and recoloring it would leave the duplicated site infrastructure in place.

SITE-2. Call: compile a small native consumer driver

Keep apps/site private. Its native driver calls Telescope's public host for build, check, serve and assembly. A compiled driver supports the required Mermaid and layers fence providers; the stock CLI has an empty provider registry. Pure adapter packages remain testable without I/O. Native host packages declare their target with a comment; all published library targets remain supported.

Use explicit immutable inputs and smart constructors for new consumer-owned paths, tree identifiers and ports that have rules. Use Telescope's supplied model types where available. Parse raw task arguments once. Keep process and filesystem work in the native driver or MoonBit task scripts using moonbitlang/async.

SITE-3. Call: keep only the content passes Telescope does not supply

Register consumer-owned mermaid and layers fence adapters. Adapt the existing renderers instead of copying the Markdown planner. Diagram SVG IDs must be distinct per block; failures retain the source and ordinal. Retain the pinned Shiki highlight post-pass and its tests if Telescope does not supply equivalent dual-theme highlighting. Check output after all passes. Generic discovery, shell, API rendering, search and browser controls come from Telescope.

Port existing acceptance fixtures to the shared host. Preserve required compiler API anchors, source links, checked MoonBit examples, unknown-language warnings, proposed banners, callouts and malformed-input failures. Do not replace compatibility evidence with DOM snapshots.

UI-1. Call: use the shared shell with a reviewed landing fragment

Observed compatibility gap: the installed Telescope 0.4.0 host generates the API index, but its page-content resolver rejects a link to /api/ with no page at site route. The shared header's API link works. The owner approved a small tested consumer compatibility adapter. The reviewed landing source uses moon-lander-route://api-index. After shared rendering, the native adapter maps only that marker to the active base plus api/, requires the generated index to exist, rejects unknown marker URLs and runs the shared output check. Published links use ordinary paths and work without browser scripts. Remove the adapter after a pinned Telescope release supports the ordinary link. The API-index requirement is unchanged.

Keep site/pages/index.html as reviewed static content inside the shared shell. Use a consumer-owned landing stylesheet with selectors scoped to its root. Link that local stylesheet from the fragment so it does not require a fork of the shared shell or a fake JavaScript island. Ordinary documentation uses Telescope's built-in Smithy tokens.

The landing page has one main heading, a short summary, docs and API actions, the standalone mascot, a selectable installation command, package guide sections and a final documentation link. Use moon add moonrockz/moon-lander without an obsolete release pin or a fixed module count. Any MoonBit source example comes from tested source. Links use logical routes that Telescope rebases for the active tree.

UI-2. Call: copy a small explicit set of brand assets

Configure header_logo and favicon using normalized output paths. Put copies of the selected existing icon exports and an optimized mascot derivative under site/assets/brand/. Map site/assets to output assets. Verify the copied icon bytes against the originals. Preserve the PNG originals in docs/assets/brand. Do not copy the originals, prompts or brand preview into the published page tree.

Exclude docs/assets/ from page discovery. Telescope also applies configured exclusions to static copies, so deployment copies must live outside this excluded directory. Preserve Telescope's normal exclusions when adding this one. The header logo is decorative beside the project title, which names the home link. No fonts or other runtime assets are fetched from a third-party service.

BUILD-1. Call: retain task names and consumer release policy

Keep build:site, check:site, test:site, dev:site and assemble:site with their current tree arguments. Pin dependencies in the existing manifests and mise configuration. Do not add shell or PowerShell automation.

Telescope serve does not watch. Keep a small MoonBit watch/build loop and delegate serving to the host. Reuse the existing release pagination, selection and download policy to produce a supplied-tree assembly manifest. Telescope performs offline assembly. Keep /moon-lander/, /next/, /v/<minor>/, /latest/, canonical links, static banners and versions.json.

Retain the current 25 KiB warning and 27 KiB failure threshold for the island bundle. The installed 0.5.1 shared island asset measures 24,915 bytes with the task's gzip measurement, below the warning threshold. The build measures the installed public package on each build. Do not silently drop or increase the limit. Optional gallery/editor assets must not be loaded on ordinary docs pages. If the released host cannot meet an existing contract, record the concrete failure and revise the proposal before broad migration.

TEST-1. Call: compare routes, then qualify complete trees

Capture a normalized route and declared-anchor inventory from the pre-migration generator. Use the same reviewed sources and explicitly exclude brand documentation from both inventories. The expected change in this proposal is the home heading and content, not a package or API route. Retain the old output only as a local test artifact, not as a second permanent generator.

Browser checks cover desktop and 390 px layouts, light and dark palette tokens, contrast, stored/system theme choice, keyboard focus, search, copy, a rendered diagram, API anchors, source links and no-script navigation. Check local and next bases and a fixture assembled from a retained historical archive.

WIN-1. Owner: consume the published Windows host repair

Windows CI exposed slash-only canonical-path handling in Telescope 0.4.0. The owner approved an upstream repair and 0.5.1 publication from source 1b0808634f9a173f6368e5e3b9ac6edde662dc16. Pin that actual release and verify the Windows consumer before merge. Keep native source-preflight separators and read-only Git fixture cleanup in Moon-Lander. No dependency source is copied or patched.

Migration plan

  1. After approval, create the beads epic and child stories for tasks.md.
  2. Prove a public-package Telescope build with real docs, API metadata, both fence providers and both deployment bases.
  3. Move all site content through the shared host. Verify routes and anchors before removing the old generic packages and islands.
  4. Add the landing page, optimized mascot, header icon and favicon. Inspect actual light and dark output on desktop and phone widths.
  5. Switch version assembly and preview tasks, then verify CI commands and documentation. Archive the change in the last implementation pull request.

Deployment remains the existing main-branch GitHub Pages workflow. Roll back by reverting the migration commit. Historical release archives remain untouched. Do not publish a library, release or live site from the workstation.

Verification

Run focused adapter, host and script tests first. Then run the existing site build, check and browser tasks at the project base and next base, plus a historical-tree assembly fixture. Run mise run format, mise run check and mise exec -- openspec validate --all --strict. Review using the repository code-review checklist and the build-master skill for task or workflow changes.

Observed references: Smithy site/public/styles.css and site/shell/view_landing.mbt; Telescope docs/cli.md, docs/presentation.md, docs/release/0.4.0.md and the public host and extension documentation. The landing mockup embeds the Moon-Lander artwork from branding commit 44549f9.
