Notebook file trees

OpenSpec change | 2026-10-29 | Approved scope, author implementation decisions

Context · Goals · Decisions · Risks · Migration

Context

See proposal.md. DIB already supports typed kernels and lossless source. Jupyter already retains arbitrary cell metadata. Both can describe one pure tree model.

Goals and non-goals

Provide one immutable text tree, a reusable DIB codec and two file mappings. Keep all logic portable and free of I/O. Disk materialization, binary entries, symlinks, execution and configuration-module dependencies are outside this change.

Decisions

VFS-1. Shared tree and typed paths (Call)

Use new files, files/dib and files/ipynb packages within notebooks. A TreePath accepts only portable nonempty relative segments. TextFile normalizes line endings to LF. FileTree stores ordered files and explicit directories, infers parents and rejects duplicate files and file/directory conflicts. Accessors return immutable values or defensive copies.

VFS-2. Kernel descriptor and configured codec (Owner)

The owner approved a small open trait returning KernelInfo and an immutable codec that applies one registry and source policy. KernelInfo itself implements the trait. No custom default means the standard registry; a custom descriptor seeds a custom registry with Markdown available. Registration returns a new codec and retains typed duplicate errors. Codec cell construction, reading and writing use one mode.

VFS-3. DIB transport (Call)

Register tree and text in the file format and select Lossless. A first-line file directive owns its path; the remainder is exact normalized file content. Later file directives are literal content. A tree cell declares explicit directories. Writers use JSON strings for paths so spaces and quotes remain unambiguous; readers also accept simple raw paths. Unmarked cells remain notes outside the projection. Registered selector collisions retain DIB refusal. No new escaping or hidden source encoding is introduced.

VFS-4. Neutral Jupyter metadata (Owner)

The owner selected metadata.vfs, without a Moon-Lander namespace. Notebook vfs metadata contains version 1 and directories. File-cell vfs metadata contains path and kernel. Source has no transport directive. Raw, Markdown and code cells map to text, markdown and other kernels. Ordinary unmarked cells, outputs and attachments remain outside the tree projection.

{"metadata":{"vfs":{"version":1,"directories":["fixtures/empty"]}}}
{"cell_type":"code","metadata":{"vfs":{"path":"src/main.mbt","kernel":"moonbit"}},"source":"let answer = 42","execution_count":null,"outputs":[]}

VFS-5. Projection and fresh export (Call)

Reading a tree never mutates the notebook. Writing a tree creates a fresh notebook and makes no promise to preserve unrelated notebook metadata, notes, IDs, attachments or outputs. Keep the original notebook for full-document editing. Per-cell kernel labels describe content; they do not make a Jupyter execution kernel polyglot.

VFS-6. Explicit conversion (Owner scope, Call policy)

The owner requested format conversion. Tree conversion uses an open format trait and the shared projection. A separate configured source-notebook converter keeps ordinary cells and kernel identity. Strict conversion refuses reported data loss; SourceOnly is explicit opt-in and returns typed losses for discarded cell IDs, metadata, outputs, execution counts, attachments and extension fields. Unknown cell types are refused. The existing Polyglot kernel metadata convention carries kernel identity; VFS paths remain in metadata.vfs.

Risks and trade-offs

RiskDecision
Generic metadata name collides with another conventionUse explicit version 1, strict shape errors and documented fields. Do not claim a Jupyter standard.
Lossless is confused with byte reproductionDocument LF-normalized text and fresh notebook export; preserve content and tree structure.
File content holds a DIB selectorKeep typed export refusal. Jupyter source can carry such text without DIB framing.
Path declarations overwrite filesReject duplicates and file/directory conflicts. No implicit overlay.

Migration plan

All APIs are additive. Existing DIB defaults and Jupyter codecs remain unchanged. Verify descriptors, same-tree examples and typed failures on four targets. Release/version decisions stay separate.
