Context

See the proposal for motivation and the launcher contract for behavior. Stock Moonx executes a verified prebuilt Wasm asset. Adjacent source-archive JS files do not provide a runtime payload directory. The Node child must retain its own host, worker layout and completion schema.

Local feasibility built a renamed async runtime with both stock compilers, proved separate parent and Node module graphs, and preserved Interrupt/130 and Terminate/143 through direct Moonrun and genuine top-level Moonx. The candidate test used a loopback registry, not an actual public publication.

Goals and non-goals

The public facade accepts work as immutable values and owns process and file lifetime. Its root policy package is pure on all four targets. Its driver owns one runtime and never exchanges async values with canonical hosting. Node sees the caller's working directory, application arguments and standard streams.

Payload assembly, hashing and embedding remain application work. This module does not select application commands, change completion JSON, install Node, change actor APIs, or replace the stock compiler or Moonrun.

Decisions

RTE-1. Owner: frozen optional runtime subset

Add moonrockz/moon-lander-moonx in pkgs/moonx. Its runtime subtree is the approved production dependency closure of async 0.22.5 root, process, signal and stdio: 21 packages, 158 source/manifest files, 646,193 original bytes and 23,428 lines before retained test support. Keep upstream types inside this frozen subtree rather than refactoring them. The new public policy facade follows the repository's domain type rules.

The immutable source archive is https://download.mooncakes.io/user/moonbitlang/async/0.22.5.zip, SHA-256 142776b3fac385b8ee97e62fb3213b02a80595ae1a4a80ede6419f452eab01c2. Keep Apache-2.0 and copyright notices. A MoonBit task owns deterministic import renaming, source/test selection, declared patches and checksums. Verification rejects drift. Retain the relevant upstream tests and required fixture provenance.

A full fork carries unrelated protocols. A thin canonical wrapper cannot read the signal. A new hand-written event loop has more semantic maintenance risk. The owner accepted the selected frozen subset. Track the return path in async #706 without waiting for that release.

API-1. Call: portable values and one synchronous driver

The root package defines opaque immutable executable, argument, relative-file, payload and positive shutdown-grace values. Parse raw strings and arrays once. Use typed error rules. Empty arguments are valid; NUL is not. File paths reject non-ASCII asset names, absolute and traversal forms, ambiguous segments and nonportable names. This restriction does not affect Unicode argv, cwd, host temporary paths or bytes. Payload construction checks duplicates, file-directory conflicts and entry membership.

Commands and Node payload launches form typed alternatives in a launch plan. The driver package provides a synchronous run entry with an optional synchronous finalizer and after-cleanup completion callback. No public facade callback carries a canonical or compatibility async type. The driver terminates the parent after cleanup, using the real child status on finite completion and the runtime's real signal termination path on cancellation.

A pure typed outcome distinguishes not-started failures or cancellation from started child completion. It retains the actual wait status, cancellation cause, hard-termination request observation, cleanup failures and selected parent status. Windows keeps the full 32-bit status. The application owns startup result JSON; the framework never reads or adds an application document on the child channel.

fn main raise {
  let arguments = @moonx.Arguments::parse(@env.args()[1:].to_owned())
  let command = @moonx.Command::new(@moonx.Executable::node(), arguments)
  @driver.run(Process(command))
}

Stock compilers hardcode canonical async for async fn main. The owned runtime instead exposes an explicit public synchronous entry around its own event loop. No canonical import is added to satisfy the compiler. Retained async tests use a synchronous test adapter for this same owned loop.

CLI-1. Public stock Moonx artifact and report ownership

The owner approved pkgs/moonx/launch inside the optional module as a narrow exception to executable placement under apps/. It is a thin caller of the public driver, with no private lifetime implementation or payload protocol. A published /launch Wasm asset provides genuine cold Moonx qualification without another public module.

Launcher options stop at -- or the first executable. Child argv and streams stay opaque. --json owns only help, usage errors and typed not-started reports; a started child owns stdout completely. Parent reports use schema version 1, command and package version, a typed report kind, selected unsigned process status and kind-specific details. Root version automation keeps the embedded package version aligned. Tests exercise actual help, startup failure, child JSON ownership, literal child options and binary streams.

SIG-1. Call: first signal, real completion and platform behavior

Record the first signal before cancelling the main task. A public typed, non-consuming observer reads it during protected cleanup. Keep the existing runtime's final process-signal handling. At child cancellation, select the observed signal and delegate to its existing graceful policy and bounded hard termination. Ordinary task cancellation uses the platform's documented default, without claiming an OS observation.

Two additional observations preserve truthful completion: a non-consuming view of the unchanged runtime exit-signal selection, and an optional synchronous notification immediately before the existing hard termination request. The reported force-request flag does not infer cause of death. The selected parent status is distinct from the first forwarding identity and actual child status.

POSIX SIGINT and SIGTERM are forwarded unchanged. Windows launching remains supported: finite processes, opaque transport, payload lifetime and its available Ctrl-Break graceful cancellation followed by forced termination. Exact stock Moonrun commits 2284bd2 and 3778465 always deliver Ctrl-Break to the owned Windows process group. Do not rename it Interrupt or invent POSIX SIGTERM there.

Qualify real Windows console behavior in CI, including an isolated-console Ctrl-C observation where feasible. New process groups disable Ctrl-C by default, so source inspection and the existing Ctrl-Break suite are not Ctrl-C proof. Any unavoidable gap in intended application cancellation semantics must return to the owner before a release contract is narrowed. Do not add a blanket Windows refusal, a guessed reason, a new application protocol or a custom toolchain.

FS-1. Call: private payload directory through reaping

Create a new directory atomically through the owned async filesystem API, with mode 0700 on POSIX. Register protected cleanup immediately. Write validated relative entries with exclusive creation and preserve their bytes and layout. Pass the absolute selected entry to Node while retaining the caller's cwd and standard streams. Do not put the payload in argv or consume stdin for it.

Close writes before launch. After finite completion, graceful stop, forced termination or startup failure, reap any owned child before removing the payload. Use the filesystem API's non-following directory entries for recursive cleanup. Finalization is idempotent and protected. It preserves selected nonzero statuses; a finalization failure changes only selected success into failure.

CI-1. Call: existing checks own the new assurance

Use the personal build-master skill; this repository has no local copy. Extend the existing lint/workspace, target tests, task-script, macOS and Windows categories. Do not add a new event or weaken ci-ok. The launcher task builds its compatible parent/Node fixtures once per compiler and reuses them across signal, payload and transport cases. Independent compilers remain distinct.

Migration plan

No existing consumer migrates automatically. Add the optional module, its documentation and consumer gate. The final feature pull request archives the implementation tasks. A separate release gate bead stays open until the owner-authorized version change publishes and independent actual-artifact proof succeeds. Recheck upstream main before selecting 0.9.0.

Releases run only in GitHub Actions. Do not overwrite a registry version or release. If verification fails, retain the evidence and repair the release gate or prepare a new approved version. Replace the frozen subset only after a public upstream observer supports both stock toolchains and passes the same process, payload, isolation and public-registry contracts.
