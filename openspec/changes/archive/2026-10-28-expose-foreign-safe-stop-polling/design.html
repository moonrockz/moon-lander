Expose foreign-safe stop polling

Issue #128, accepted into the active 0.7.2 patch.

Context | Goals | Decisions | Risks | Migration

Context

See proposal.md. A Promise callback has no current coroutine. Lifetime.cancelled queries the current task when no stop request exists. The private probe_stop already reads registered probes and the retained request without that query.

Goals and non-goals

Expose one safe read of the existing stop state. Keep task-aware cancellation and all existing lifecycle rules. Do not add a second state, scheduler or cross-thread guarantee.

Decisions

API-1. Expose stop_requested (Call)

Lifetime.stop_requested delegates to probe_stop. Context and StopToken delegate to that lifetime method. The name describes a host stop request and does not claim current-task cancellation. Foreign callbacks run on the host thread and must obey the existing cheap, non-raising probe contract.

STATE-1. Keep one lifetime (Owner)

Use the same request_stop path, first reason and signal precedence. Keep cancelled and check_cancelled unchanged.

Risks and trade-offs

The new read can observe a signal and request command cancellation, as probe_stop already does. Test the actual Promise callback, including no-stop false, application stop, non-yielding signal and first reason. A true result does not yield or run cleanup. Task-only cancellation must remain distinct.

Migration plan

Add the API in 0.7.2 with issue #127. Callers bind synchronous foreign probes to stop_requested. Keep task-aware checks inside run tasks. Verify published archives and fresh registry consumers before Morphir adoption.
