Context

See proposal.md for the reason. The requirements are in sigstore-bundle-verification, sigstore-identity-policy, sigstore-trusted-root and framework-publication.

The research read sigstore-go be417d9, sigstore-python 19b8aec, protobuf-specs 6d0a62a, rekor-tiles 16bc64c, the Sigstore client specification (architecture-docs 82f7d95), sigstore-conformance acb38c9, cli/cli 30eb70c and actions/attest 4d7d407. When sigstore-go and the prose specification disagree, this design follows sigstore-go, because gh attestation verify uses it.

Goals and non-goals

Goals:

  • Verify the bundles that actions/attest makes for public repositories, with the same result as gh attestation verify, on wasm, wasm-gc, js and native.
  • One synchronous, I/O-free call that a test can run with fixed inputs.
  • A failed verdict that tells the CLI which check failed, and tells "invalid" from "not supported".

Non-goals: the items in the proposal's "Out of scope" list, constant-time code (verification holds no secrets), and speed beyond a few milliseconds for each bundle.

Verification pipeline

The order follows sigstore-go pkg/verify. Each box gives one failure family of the verdict. The verifier stops at the first failure.

Exact rules for each step
  1. Parse. Media type application/vnd.dev.sigstore.bundle+json;version=0.1|0.2|0.3 or application/vnd.dev.sigstore.bundle.v0.3+json. Content is dsseEnvelope or messageSignature. Material is certificate, or x509CertificateChain for v0.1 and v0.2 (only the first certificate is used). v0.3 refuses x509CertificateChain. A publicKey is not supported. At most 32 log entries. Unknown fields fail. Bytes accept standard and URL-safe base64, with optional padding. 64-bit integers accept a string or a number.
  2. Log entry. Exactly one Rekor v1 entry is used. Find the log by hex(logId.keyId) in tlogs; for an ECDSA log, the ID is SHA-256 of the DER key. Kinds: dsse/0.0.1 and hashedrekord/0.0.1; intoto/0.0.2 and v0.0.2 kinds are not supported. SET payload: {"body":"<base64 canonicalizedBody>","integratedTime":N,"logID":"<hex keyId>","logIndex":N}, in this key order with no spaces; ECDSA verify over SHA-256 of it. The integrated time is inside the closed range of the log validFor, and not after "now".
  3. Inclusion. Required for v0.2 and later. Leaf hash SHA-256(0x00 ∥ body), node hash SHA-256(0x01 ∥ left ∥ right). With inner = bitlen(index xor (size − 1)) and border = popcount(index >> inner), the hash count is inner + border, and index < size. Use inclusionProof.logIndex, not the entry index. Checkpoint: split at the last blank line; the note text keeps its last newline; a signature line is — <name> <base64(4-byte key hint ∥ DER signature)>; the key hint is the first 4 bytes of the log ID; ECDSA verify over SHA-256 of the text. The third text line (base64 root hash) equals inclusionProof.rootHash.
  4. Certificate. For a Fulcio CA in the root whose validFor holds the integrated time, build the path leaf → CA intermediates → CA root (the bundle gives no intermediates in v0.3). Each certificate is valid at that time (bounds inclusive). Each signature verifies (public good: ECDSA P-384 with SHA-384). CA certificates have basic constraints CA true and obey path length. The leaf has EKU code signing and key usage digital signature. An unknown critical extension fails, except SAN, which Fulcio marks critical.
  5. SCT. Extension 1.3.6.1.4.1.11129.2.4.2. Find the CT log by key ID in ctlogs; the SCT time is in its validFor. Signed data: 0x00 ∥ 0x00 ∥ timestamp u64 ∥ 0x0001 ∥ SHA-256(issuer SPKI) ∥ u24 length ∥ TBS without the SCT extension ∥ u16 extensions length ∥ extensions; ECDSA with SHA-256.
  6. Log body. Decode canonicalizedBody. Its kind and version equal kindVersion. Its signature equals the bundle signature. Its PEM verifier decodes to DER that equals the leaf DER. For DSSE, payloadHash equals hex SHA-256 of the payload; for hashedrekord, the digest equals the message digest.
  7. Content. DSSE: payload type application/vnd.in-toto+json; exactly one signature; PAE = "DSSEv1" SP len(type) SP type SP len(body) SP body, lengths in ASCII decimal; verify with the leaf key (P-256 with SHA-256, P-384 with SHA-384). Message signature: verify over the digest.
  8. Artifact. The statement has at most 1024 subjects and 32 digests for each. The SHA-256 artifact digest equals one subject's sha256, hex compared without case. For a message signature, it equals messageDigest.
  9. Policy. See POL-1.

Decisions

MOD-1. One new module, moonrockz/sigstore

Owner, approved 2026-10-30 (name and publication). Add pkgs/sigstore as the module moonrockz/sigstore, next to moonrockz/openrpc and moonrockz/notebooks. It does not import a framework module, and no framework module imports it, so the framework layering in AGENTS.md does not change. The name has no moon-lander- prefix because the verifier is not a framework layer, and a program that is not a Moon-Lander application can use it.

Alternatives: moonrockz/moon-lander-sigstore (says that it needs the framework, which is false); a package in moon-lander-core (adds crypto dependencies to every application).

MOD-2. Package layout

Call. The public API is in the module root package. The building blocks are internal packages, so they are not public API and can change without a breaking release.

pkgs/sigstore/
  moon.mod                 moonrockz/sigstore; imports moonbitstack/mooncrypt (exact pin)
  moon.pkg                 root: Bundle, TrustedRoot, Policy, Verdict, verify
  bundle.mbt  trusted_root.mbt  policy.mbt  verify.mbt  verdict.mbt
  public_good.generated.mbt          the pinned public-good root
  internal/
    der/        strict DER reader, and the TBS rewrite for the SCT
    x509/       certificate fields, Fulcio extensions, path checks
    signature/  ECDSA over mooncrypt: DER signature, key checks, curve choice
    tlog/       SET payload, RFC 6962 proof, signed checkpoint
    sct/        embedded SCT list and precertificate data
  testdata/                          source fixtures (not built)
  fixtures/                          generated test-only fixture constants

CRY-1. Pure MoonBit crypto, with SHA-2 and ECDSA from mooncrypt

Owner, approved 2026-10-30. Use pure MoonBit on every target. Import moonbitstack/mooncrypt at the exact version 0.4.4 for hash/sha2 and sign/ecdsa. Our internal/signature package wraps it: it parses DER signatures strictly, converts them to r∥s, refuses public points that are not on the curve or have a coordinate ≥ p, and selects the curve and hash from the key. The Wycheproof DER and P1363 sets for P-256/SHA-256 and P-384/SHA-384 run in mise run check on all four targets, so a version change must pass them before it lands.

Why: host crypto makes the js API async and needs three adapters, and wasm has no host crypto. mooncrypt already passes the full Wycheproof sets on the four targets. Alternatives: write SHA-2 and ECDSA in-house (about 600 lines; the prototype shows that it works, and it is the fallback if mooncrypt breaks or goes away); WebCrypto and C stubs (see Platform crypto).

CRY-2. Our own strict DER and the Fulcio X.509 subset

Call. Write a small DER reader and the X.509 fields that Sigstore needs: TBS bytes, signature algorithm and value, validity, SPKI, basic constraints, key usage, EKU, SAN, authority and subject key IDs, the Fulcio extensions and the SCT list. mooncred drops non-critical unknown extensions, which removes the Fulcio claims and the SCT, and the SCT check must rebuild the TBS without one extension. The Sigstore path is short (leaf, intermediate, root) and uses ECDSA only, so the path check is small.

CRY-3. Algorithms

Call. ECDSA P-256 with SHA-256 and P-384 with SHA-384, as sigstore-go selects them from the key. Also P-384 with SHA-256 as a second try for bundles up to v0.3, as sigstore-go does. Ed25519 (Rekor v2 logs) and RSA keys give a not-supported reason. SHA-512 is in mooncrypt and costs nothing, but no step needs it now.

API-1. Parse at the boundary, then one pure call

Call. Each input has a type with a smart constructor. The verify call takes only parsed values, so it does not check input syntax again.

let bundle = @sigstore.Bundle::parse(bundle_json)            // raise BundleError
let root = @sigstore.TrustedRoot::public_good()              // or TrustedRoot::parse(text)
let digest = @sigstore.ArtifactDigest::parse("sha256:03d1…")  // raise DigestError
let policy = @sigstore.Policy::github_workflow(
  @sigstore.GitHubRepository::parse("finos/morphir-rust"),
  workflow=@sigstore.WorkflowPath::parse(".github/workflows/release-provider-snapshot.yml"),
  hosted_runner_only=true,
)
let now = @sigstore.Instant::from_unix_seconds(clock_value)  // the caller reads the clock
match @sigstore.verify(bundle, digest, root, [policy], now) {
  Verified(facts) => facts.statement.predicate_type
  Rejected(reason) => reason.to_string()
}

The verify call is synchronous and does no I/O. The CLI keeps the bundle JSON in its lock file and calls the same function again later.

API-2. Verdict and reasons

Call. Verdict is an enum: Verified(VerifiedBundle) or Rejected(Rejection). Rejection is Unsupported(Feature) or Invalid(Failure). Feature names Rekor v2, timestamp authority, public key, an entry kind or a key type. Failure has one case for each pipeline step, with the values that a user needs (for example IssuerMismatch(expected~, actual~)). A parse error is a suberror, because the caller has no verdict before it has values. VerifiedBundle holds the statement (predicate type, subjects, raw payload bytes), the matched policy index, the certificate claims, the log ID, the log index and the integrated time.

Alternative: raise on a failed check. Rejected, because a failed verification is an expected result that the CLI shows, not an exception.

TIME-1. One time source

Call. The verified SET integrated time is the only time for the certificate and SCT checks, as in sigstore-go, where a log time counts only with a verified SET. "now" only bounds the integrated time. The library never reads a clock.

SCOPE-1. Rekor v1 and public repositories first

Owner, approved 2026-10-30. Support Rekor v1 entries with a SET. Do not support RFC 3161 timestamps, Rekor v2, or GitHub's private Sigstore instance in this change. The result: attestations from private repositories and GitHub immutable-release attestations get Unsupported(TimestampAuthority). All current morphir publishers are public. RFC 3161 needs a full CMS SignedData check, which is about as large as the rest of this change. Rekor v2 needs Ed25519 and RFC 3161. Both are a later change, and the typed reasons let the CLI say why it refuses.

SCOPE-2. Message signatures too

Call. Also verify messageSignature bundles with hashedrekord/0.0.1 entries. GitHub does not make them, but most conformance cases use them, and the extra code is a digest compare and one signature check.

JSON-1. Strict hand-written decoders over core JSON

Call. Decode the bundle, the log body and the trusted root from core @json values with hand-written decoders that follow protobuf JSON as sigstore-go reads it (see the parse step above). Generated protobuf code needs protoc and does not accept URL-safe base64. Build the SET payload as text from its four values instead of a general canonical JSON library.

A trusted root key that is not an ECDSA SubjectPublicKeyInfo, such as the PKCS#1 RSA CT log key (PKCS1_RSA_PKCS1V5) in conformance roots or the Ed25519 Rekor v2 key, is kept and marked not usable, as sigstore-go keeps it. A bad ECDSA key is a parse error.

POL-1. Policy model

Call. A Policy holds an Issuer (default https://token.actions.githubusercontent.com), an identity (ExactSan(SanUri) or SignerWorkflow(repository, path, ref?)), and optional claims: source repository, owner, repository ID, owner ID, source ref, and hosted-runner-only. There are no regular expressions: a signer workflow matches the SAN https://github.com/owner/repo/path@ref on exact parts, so release.yml does not match release.yml.evil.yml. The Morphir trust record should pin the repository ID and the owner ID, because a deleted and recreated repository has the same name and a new ID. Claims read the DER UTF8String extensions .1.8 to .1.22, and the raw .1.1 issuer when .1.8 is absent.

TRUST-1. Pinned public-good root

Call. Keep the root source at pkgs/sigstore/testdata/public-good/trusted_root.json (root-signing c9bda74). A moonx script, scripts/generate-sigstore-assets.mbtx, writes it into public_good.generated.mbt as a string constant. Its --check mode runs in mise run check, as the OpenRPC artifact scripts do. A test checks the SHA-256 digest. A TUF client that refreshes the root is a later change.

TST-1. Fixtures on targets without a filesystem

Call. wasm and wasm-gc tests cannot read files. The same script writes the vendored conformance cases, the real GitHub bundles and the Wycheproof vectors into test-only generated .mbt files, and --check rejects stale output. Negative real-bundle cases are made in the tests by changing one field of a valid fixture. The conformance and Wycheproof files are Apache-2.0; their license and source commit go next to them in testdata/. mise run check:sigstore fails when a target runs zero sigstore tests, as check:actors does. A full run of the Python conformance harness through a CLI is not part of this change.

Implementation result: all 70 conformance cases are vendored, and a test pins the outcome of each one. The 6 Rekor v1 pass cases pass; each Rekor v1 _fail case fails with its expected reason; the Rekor v2, managed-key and timestamp cases give a not-supported reason or fail to parse. The 1,530 Wycheproof ECDSA cases give their expected result on all four targets. The published archive leaves out the testdata/ sources through pkgs/sigstore/.moonignore, but keeps the generated fixtures and their license notices, because moon resolves test imports when it builds an archived module.

Migration plan

This adds a module and changes no existing API. The publication allowlist grows to eleven libraries. The first release that contains the module needs owner approval, as for every release. If the module must go back, remove it from moon.work and the allowlist before a release.

Open questions

  • Report the two mooncrypt defects upstream (Ed25519 tcId 151; no x or y < p check in PublicKey::new). Our wrapper does not depend on the answer.
  • Whether the P-384 with SHA-256 second try is needed for any real bundle. It does not change the API.
