Context

See proposal.md. Lifetime already has a private Embedder stop request. The console drivers always install their own OS handlers or Node listeners. Node workers do not receive the parent's OS signal events, and a busy worker cannot yield merely to receive an event.

Goals and non-goals

Expose existing stop machinery through typed public inputs. Preserve stop reasons, cleanup, finalization and exit mapping. Keep the installed-listener default. No cross-thread calls into MoonBit, arbitrary reason injection or new production Node adapter is added.

Decisions

HOST-1. Public embedder request (Owner: actual Embedder reason; Call: method)

Add Lifetime::stop_from_embedder with the same optional ExitCode as stop_application. It forwards to the existing private request_stop with Embedder. The first event still owns the run reason. Cancellation, ordered stop phases, failures and shutdown budgets use the existing engine. A callback obtains the lifetime from a public Context hook; no new lifetime constructor is exposed.

SIG-1. Public read and optional console probe (Owner: enclosing reader; Call: ownership)

Add SignalProbe::read and an optional signals argument to native and JS console run. A supplied probe replaces console ownership of OS listeners. The native path disables async global cancellation signals without installing the C stub. The JS path installs no signal listeners. Both retain the console run, reports, finalizer, output draining and exit selection.

A sticky first-signal reader contains no event count. Polling it repeatedly cannot count as repeated signals. Combining two owners for the same OS signal could count one event twice or replace the launcher's handlers. Explicit external ownership avoids that ambiguity. It is documented as part of the new opt-in contract.

SIG-2. Latch one observed signal per console run (Call)

Wrap the supplied reader in a private per-run latch. Once a SignalKind is observed, retain it through hooks, finalization and exit selection even if a consuming reader later returns None. Pass that same latched reader to hosting.run and finalizer selection. A signal first seen during finalization still takes signal exit precedence. This does not fabricate a reason after the run; the host sees the typed signal through its ordinary probe.

TEST-1. Public runtime acceptance (Call)

Use public-host tests for an active command stopped by a captured lifetime. Use an unpublished Node parent/worker fixture for SIGINT and SIGTERM: the parent publishes SignalKind through shared state, and the worker polls the public cancellation check without suspension. Assert stopping reasons, reverse cleanup, selected 130/143 and one protected async finalization. MoonBit task scripts own build and process lifecycle. Worker-only Node interop stays in unpublished fixtures. Existing installed-listener and second-signal tests remain unchanged.

Risks and trade-offs

Migration plan

Existing calls remain unchanged. A desktop callback calls stop_from_embedder. A launcher passes its SignalProbe through console.run. Land the two task groups with their public tests, then publish in the shared release. See the requirements. The separately approved diagnostic JSON contract is required release scope and has its own logging change.
