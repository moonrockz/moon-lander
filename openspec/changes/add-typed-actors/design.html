Context

See proposal.md for the problem and scope.

The async mediator has typed async handlers, but no private mailbox or task that outlives a send. moonbitlang/async 0.22.5 supplies task groups, cancellation, queues and condition variables. Its queue has no selective receive operation. The runtime is cooperative. The existing async mediator supports wasm, js and native; wasm requires the embedder event loop imports. There is no async event loop on wasm-gc.

Labels identify the source of a decision. Owner means the user requested it. Call means this proposal chooses it for review.

Goals and non-goals

The default path needs a protocol, a handler and one start call in an owned scope. Advanced operations must use the same mailbox and lifetime rules. The framework must not require names, registration or a service container.

The API does not promise BEAM process isolation. MoonBit references can alias mutable values. Applications must transfer ownership by convention, use immutable messages, or copy at their own boundary.

Decisions

ACT-1. Local actors and typed protocols (Owner)

Each actor has one private mailbox and one consumer task. ActorRef[M] accepts only M. A protocol is an ordinary MoonBit enum or another application type. A send enqueues work; it never calls the handler on the sender's task. Actor state is private to its task. Different actors can make progress when one actor waits. This gives concurrency, with no promise of CPU parallelism.

MOD-1. A standalone module with a target-limited runtime (Call)

Use pkgs/actors for moonrockz/moon-lander-actors. The root package contains portable mailbox policies, checked limits and immutable lifecycle values. moonrockz/moon-lander-actors/runtime, normally imported as @actors, contains scopes, handles, reply destinations and operations that wait.

The runtime declares supported_targets = "wasm+js+native", with a comment that explains the event loop limit and when to remove it. The portable root builds and tests on all four targets. Runtime acceptance tests must run on each of its three targets and must fail if a target runs zero tests.

The module imports only core and moonbitlang/async 0.22.5. It adds no host dependency and no reverse dependency from existing modules. The umbrella may depend on actors, but this change does not add that dependency or re-exports. Update the framework module and publication policies for the additional module. Publish actors after core and before any future dependent module.

Alternative: put actors in mediator. Rejected because actors have a distinct lifetime and should be usable without mediator. A new scheduler is unnecessary.

ACT-2. A scope and two ordinary entry points (Call)

Group 1 compiled this form with the pinned compiler on wasm, js and native (see Feasibility evidence). The generic types are inferred at the call sites.

enum CounterMessage {
  Increment
  Read(@actors.Reply[Int])
}

async fn counter_example() -> Int {
  @actors.scope(scope => {
    let counter = scope.start(0, (state, message) => {
      match message {
        Increment => @actors.Continue(state + 1)
        Read(reply) => {
          ignore(reply.send(state))
          @actors.Continue(state)
        }
      }
    })
    counter.send(Increment)
    counter.ask(reply => Read(reply))
  })
}

start(initial, handler, mailbox?, on_stop?, name?) returns Actor[M, Unit] once the mailbox and owner registration exist. The handler is async (S, M) -> Next[S]. Continue(state) supplies the next state; Stop ends normally and discards queued messages. Next[S] is a plain enum with these two cases, because continue is a reserved word and cannot name a function. Without an initializer, start does not wait and raises only a typed start error. A protocol can model different behavior modes in its state enum. No behavior class is required. An optional initializer form runs inside the actor task and reports startup failure before publishing a usable handle. Register cleanup after acquisition and before reporting readiness. Partial acquisition cleanup belongs to the initializer.

spawn(inbox => body, mailbox?, name?) returns Actor[M, R]. It supports custom receive loops and an arbitrary final result R. Inbox gives receive, scan, self, reenqueue and child creation. Only the actor body gets the inbox, and no public constructor can make a second consumer for the mailbox. The pinned moonbitlang/async gives no public task identity, so the runtime cannot see which task calls an inbox operation. It enforces the single consumer in two cases: a receive or scan while another one waits, and any receive after the body has ended. Both fail with the typed ownership error and remove no message. A body that hands its inbox to another task while it does not receive itself is outside this check; documentation must state it.

The handle forwards message operations and exposes to_ref() for a send-only reference (ref is a reserved word in the pinned compiler). A reference cannot receive, stop, cancel or join the actor. join() waits for completion and returns R, rethrows the original failure, or reports actor cancellation. Cancelling a join waiter does not cancel the actor. status() gives an immutable snapshot; it is not a mutable public state record.

Alternative: an ActorSystem plus actor classes and registration. Rejected because none of those steps are needed to create a local mailbox task.

RECV-1. Receive loops and selective receive (Call)

Inbox::receive(timeout?) takes the oldest queued message, or waits. An omitted limit waits until a message arrives or the mailbox closes. A timeout raises a typed TimedOut; a closed empty mailbox raises MailboxClosed. try_receive(timeout?) gives None only when its wait expires. With no limit it polls once. It still reports mailbox closure as an error.

scan(select, timeout?) scans oldest first. select : (M) -> T? raise? must be pure and must not suspend. The error-polymorphic type accepts a named pure function as well as a selector that raises. Only the first matching message is removed. Non-matching messages keep their relative order. The selected result can itself be an async closure, so the F# form of a selected async computation is expressible. try_scan gives None on expiry or an unsuccessful poll. Selector failure leaves the message in the mailbox and propagates to the receive-loop caller.

A scan checks queued messages before it waits. Wake it on new admission or closure. Continue from the first not-yet-tested message during a pending scan. A new scan starts at the oldest queued message. Use an internal deque and condition variables; do not remove messages to an uncounted stash.

receive_all, receive_n and receive_loop helpers cover processing until close, at most a checked positive count, and a state loop that can return a final result. They treat MailboxClosed as normal loop completion. A custom body can catch that error and return its own result.

Selectors can starve other message kinds. A full bounded mailbox containing only non-matches also prevents admission of a future match. Document this case; use a time limit, consume a non-match, or opt into an unbounded mailbox. No priority message bypasses capacity.

ADM-1. Backpressure and admission (Call)

Default to Bounded(MailboxCapacity::default()), which is 128 queued messages. The capacity excludes the in-flight message and includes every message that a scan skips. Unbounded is an explicit policy. There is no silent drop or overwrite policy.

send suspends while full and returns at admission. try_send never waits and returns Accepted, Full or Closed. Sending after close raises a typed closed error. FIFO means admission order. Concurrent producers have no extra total order promise. No accepted message is delivered more than once by the runtime, and no accepted message is retried automatically.

Admission and cancellation have one commit point. Cancellation before admission leaves no message; cancellation after admission cannot retract the message. Remove cancelled producer waiters and wake all waiters on close. Self-send can deadlock while full. reenqueue is a non-waiting append at the tail with the same capacity result as try_send. Use it instead of a waiting self-send.

queued_count() is a snapshot of unprocessed messages, not a readiness test. Yield between bounded processing batches so a busy actor does not monopolize the cooperative scheduler. A synchronous handler that never yields can still block the entire runtime.

ASK-1. Request/reply and destinations (Call)

ActorRef[M]::ask(build : (Reply[R]) -> M, timeout?) -> R makes a fresh one-shot reply destination. The default limit is 30 seconds. A typed wait policy selects Within(TimeLimit) or UntilStopped for an explicit indefinite wait. One deadline covers mailbox admission and the reply when the wait is finite. Register the pending request before admission. Race its reply with termination so close or failure cannot strand the caller. When admission fails because the actor ended, also while the ask waits for space in a full mailbox, the ask reports the recorded outcome: a failure keeps its cause. try_ask gives None on timeout; closure and failure remain typed errors. An application rejection is a reply such as Result[Value, DomainError].

Reply::send is synchronous and non-waiting. It returns Delivered or Expired, where expired includes an already answered destination. The first reply wins. A late reply must not crash the receiving actor. Ask timeout and caller cancellation release the reply waiter but do not undo admitted work or cancel the actor. Normal termination without a reply reports Closed; failure reports a typed actor failure with the original error as its cause.

Subject[M] is a send-only destination with send and try_send. Actor references, one-shot replies, async queues and caller-supplied send functions have adapters. contramap adapts a message into a larger protocol before admission. It does not create a second queue or task. A reply adapter maps Expired to Closed. An ask to a general subject uses the same deadline and one-shot reply but can observe target termination only if the destination supplies that signal.

Alternative: dynamic response casts or an implicit sender slot. Rejected because a typed reply in the protocol gives the compiler the reply type.

SVC-1. Serialized service calls and automatic responses (Call)

scope.create(service, on_stop?) -> ServiceRef[S] is the Ox-style entry. service.ask(s => operation(s), timeout?) runs an async closure on the actor task and returns its result. Each call can have a different result type. service.tell(s => operation(s)) admits a closure without waiting for its result. Service state never appears in the public handle. The constructor transfers ownership by convention; captured aliases still need application care.

Service handles forward join, status, drain and cancel. Service close releases queued callers and returns Unit; queued implementation closures are never exposed. The pending protocol-message snapshot belongs to Actor[M, R] close.

An ordinary ask closure error passes to that caller unchanged and the service continues. Mutations before the error remain; there is no rollback. An uncaught tell closure error fails the service and its owner scope. Cancellation of an ask waiter follows ASK-1 and does not interrupt an admitted closure. Runtime task cancellation remains a control signal and is not caught as an ordinary error.

scope.respond(handler, mailbox?) -> RequestActor[Req, Res] is a smaller entry for an async request handler. actor.ask(req) replies with the handler result automatically. A handler error terminates this actor and wakes all pending callers with its cause. Use Result for a per-request rejection. These helpers use the same runtime and admission rules, not separate executors.

LIFE-1. Close, cancellation, cleanup and failure ownership (Call)

Actor[M, R]::close() atomically rejects new admission, removes queued work and returns an immutable Pending[M] snapshot once. Later closes return no snapshot. The in-flight message may finish. Close does not wait for it; join() does. Ordinary start loops end after that message. Custom bodies can catch closure and finish. A separate drain() rejects new admission, processes the admitted queue, and waits for normal completion. It needs a caller time limit when a custom body or selective receive might never consume the queue.

Fail asks attached to discarded work immediately. Let an in-flight ask reply until its actor actually terminates or its deadline ends. cancel() discards queued work and cancels the running task at a cooperative cancellation point. Repeated terminal operations cannot run cleanup twice.

scope wraps a task group but does not expose it. Before its body returns, it marks itself closed and cancels all live actors. It then joins actors and their cleanup. It never waits for an infinite receive loop before requesting cancellation. Escaped scope handles reject new starts with a typed error instead of calling TaskGroup::spawn after the group has ended.

During scope exit, a waiter can wake because a peer actor ended, just before its own cancellation takes effect. Such a waiter (a send, receive or ask) observes its cancellation, not Closed. Otherwise an actor that asks a sibling would fail the owner scope with an error that only the teardown caused. The task group keeps the last failure even after its body completed, so this rule is necessary for a clean scope exit.

A child created through the actor's inbox belongs to that actor. Parent exit, including successful completion, cancels and joins descendants. An uncaught actor error fails the owner scope and cancels siblings. Catch and recover in the body, or use a nested scope, to choose a different failure boundary. There is no automatic restart strategy in this change. A reply carrying a domain error is not an actor failure.

Cleanup runs once after processing ends, including on cancellation. Synchronous cleanup can use defer. Optional async cleanup runs with cancellation protection and a default 5-second TimeLimit, which the caller can replace. Preserve the primary failure and any cleanup error in a typed combined error. Cleanup failure fails the owner scope even if the actor was cancelled. A cleanup timeout cannot preempt synchronous code that never yields.

TOPIC-1. Typed subjects and scoped event delivery (Call)

Provide a small Topic[M] over subjects. scope.subscribe(topic, subject) returns an unsubscribe handle and binds it to that explicit actor scope. publish sends to the current subscriber snapshot in subscription order, waits for admission, and prunes closed subjects. Messages go through each destination's mailbox. It does not wait for handlers. Unsubscribe prevents inclusion in later snapshots; a publication already in progress can still deliver.

A full subscriber applies backpressure. If the publisher is cancelled or a custom subject raises, earlier admissions remain; later subjects are not called. No atomic broadcast or exactly-once business action is promised. Close rejects later publish and subscribe operations and releases registrations. Two concurrent publications have no cross-subscriber total order promise.

This differs from mediator topics, which invoke and await handlers. Keep the two types separate. Provide a worker-pool example with direct send for work and a topic for observations. Do not create a second router or pool framework.

TYPE-1. Domain values and evidence (Call)

Use opaque MailboxCapacity and MessageCount with positive Int ranges. Their smart constructors raise typed errors that hold the input and rule. Use core TimeLimit for all timeouts and cleanup budgets. Bounded versus unbounded policy, admission outcomes and lifecycle reasons are enums. Do not expose raw mutable queues, task groups, reply cells or state records. No names or string IDs are needed for an anonymous actor.

ActorName is also a portable root type, re-exported by the runtime for the one-import examples in NAME-1. The runtime owns address allocation and scope name reservations. It must not expose address constructors that let callers forge an existing actor identity.

Group 1 must prove generic closure invocation without Any or runtime casts, scope exit of an idle actor, request completion during termination, and a scan that retains non-matches within capacity. Use task/queue acknowledgements for ordering tests. Sleeps are only for actual deadline tests. If the spike cannot provide these properties, revise this design before the remaining groups. The spike provided them; Feasibility evidence lists the results and the resulting revisions.

NAME-1. Optional names, local addresses and typed discovery (Owner: useful names and addressing; Call: API and rules)

Actor scopes own name reservations as part of lifetime management. Directories are immutable values with the operations of DIR-1. No separate registry is required. The proposed glossary is in CONTEXT.md.

ValueMeaningBehavior after replacement
ActorNameA reusable label reserved within an owner scopeCan be reused after the old lifetime ends
ActorAddressOpaque identity of one actor lifetime, with optional name metadataRemains the address of the old actor
ActorRef[M]Typed authority to send to that exact actorRemains closed; never redirects
Directory[M]An immutable collection of actor references with protocol MKeeps its exact members until a new value is made

Anonymous startup in ACT-2 stays valid and needs no directory allocation. Every actor has an address, named or anonymous. Handles and references expose address(). Address equality means the same lifetime, including across copied references. Allocation must distinguish actors in separate scopes and later actors that reuse a name. An address is not a network endpoint, durable identifier or send capability. Its text form is diagnostic and cannot be parsed into authority.

For a named actor, use the optional checked name at the start call. The example uses the protocol and handler from ACT-2. handle_counter names that handler.

let name = @actors.ActorName::parse("counter")
let counter = scope.start(0, handle_counter, name~)
let counters = @actors.Directory::of(counter.to_ref())
let found = counters.lookup(name)
let exact = counters.resolve(counter.address()) // ActorRef[CounterMessage]?

The scope reserves a name before initialization or user code runs. Only one creator can reserve the same name within that scope, across all message types. A duplicate raises typed NameInUse before the losing initializer runs. Other scopes may use the same name. Named child actors use their parent's child scope. Start returns a usable handle only after initialization and owner registration finish. Initializing actors cannot enter a directory because no reference has been returned yet. Startup failure returns to the creator after cleanup; a creator that catches it can retry in the same live scope. Once started, the actor follows LIFE-1's failure rules.

ActorName::parse accepts 1 through 128 ASCII characters. The first is a letter; later characters are letters, digits, underscore, hyphen or dot. Names are case sensitive and are not trimmed or normalized. A dot is a literal character. Fields are private. Parse failures retain the input and an enum rule. Parse once at the input boundary and pass the checked name onward.

A name stays reserved until processing and cleanup end, including after close, drain or cancellation begins. Scope finalization releases only its own actor's reservation. A later start can reuse the name with a fresh address. Existing references keep the old mailbox and return closed. Directory values holding those references remain structurally unchanged. Adding a replacement is explicit.

Directory lookup is structural, uses only the supplied value, and fixes its message type M at construction. It does not inspect a process-global registry, search parents, poll actor status or cast an arbitrary protocol. A directory can hold references from several scopes without acquiring ownership of their actors. Scope exit does not invalidate the directory value; sends to its stopped members follow the ordinary closed-actor rules.

Named discovery applies to message actors. A closure service can be shared directly through its typed service reference and exposes its own address. Give it an explicit message protocol to include it in a message directory. This change adds no registry of arbitrary service objects or live directory subscriptions.

DIR-1. Directory algebra (Owner: composition, addition and removal; Call: set semantics and syntax)

Treat Directory[M] as a finite immutable set of ActorRef[M], keyed by exact actor address. Named and anonymous references are both members. Constructors and operations never start, stop, cancel, drain, rename or reparent an actor. A directory contains only send capabilities and cannot expose lifecycle handles.

OperationResult
Directory::empty()The empty directory
Directory::of(ref)One member
a.union(b) or a + bAll members, deduplicated by address
a.add(ref)Union with one reference
a.remove(ref)A new directory excluding that exact address
a.difference(b) or a - bA new directory excluding every address in b

The methods are the basic API. Add and Sub forward to union and difference. Group 1 compiled the following example on all runtime targets.

let combined = dir1 + dir2
let extended = combined.add(extra.to_ref())
let restricted = extended.remove(counter.to_ref())
let difference = extended - dir2

The algebra uses membership equality, not construction order or actor status. It has these laws for directories with the same protocol:

empty + a = a = a + empty
(a + b) + c = a + (b + c)
a + b = b + a
a + a = a
a.add(r).add(r) = a.add(r)
a.remove(r).remove(r) = a.remove(r)
a - empty = a
a - a = empty
(a + b) - c = (a - c) + (b - c)

Removal of an absent member is a no-op. Addition and removal are not general inverses: a.add(r).remove(r) = a holds only when r was absent from a. Removing an old reference never removes a replacement that shares its name. Equality ignores iteration order; enumeration has no ordering promise. Combining different protocol types is a compile error.

Name lookup returns Missing, Found(ref) or Ambiguous(conflict). Union keeps two different actor addresses even if their names match. It does not silently override either member. The conflict is an opaque immutable value that carries the name and at least two distinct matching references; callers cannot construct an invalid conflict. Repeating the same address does not create ambiguity. Removing all but one matching reference makes lookup unambiguous again. This choice keeps union total, associative, commutative and idempotent.

resolve(address) returns the exact member or None. Lookup and resolve may return a closed actor reference because membership is independent of liveness. Stopping an actor does not change an existing directory. To expose its replacement, produce a new value such as old.remove(old_ref).add(new_ref). Removing a reference does not revoke copies or cancel admitted messages. It also does not release the actor's scope name reservation.

The exact requested operator spellings need a language qualification. A scratch compiler probe on MoonBit 0.10.17+d971670cd, with all four targets, accepted same-type Add and Sub. It rejected a ++ b with an unbound ~+ error and rejected a heterogeneous Add implementation with an incorrect-trait-type error. The pinned Add/Sub traits have Self, Self -> Self signatures. Thus the supported forms are dir1 + dir2, dir1 - dir2, dir.add(ref) and dir.remove(ref). Singleton conversion also permits dir + Directory::of(ref) and the equivalent subtraction. Do not promise dir ++ dir, dir + ref or dir - ref on this pin. See the official operator documentation.

Alternative: a composition of live scope registries. Rejected because membership would change as actors start or stop and removal would need a separate rule for future registrations. Another alternative is name-keyed override. That can be associative with a fixed bias but makes merge order choose an actor. Exact-address set membership keeps conflict handling in the lookup result.

Risks and trade-offs

RiskMitigation
Selective receive can block a full bounded mailbox.Document the case and test timeout and cancellation without losing or moving messages.
Service closures can capture aliases or return mutable references.Document ownership and show immutable request/reply in the main example.
Cooperative cleanup can hang in synchronous application code.State the limit and test budgets only with operations that yield.
A subject made from custom functions cannot promise those functions obey mailbox semantics.Test supplied adapters and state the custom contract.
Several convenience entry points could drift.Keep one mailbox/lifecycle implementation and run the same admission and termination acceptance cases through each entry point.
New publication inventory can omit a consumer or asset.Extend the explicit allowlist and isolated candidate audits in the first lasting module change.
A name can be reused while an old reference still exists.Give every lifetime a fresh address and test stale lookup, sends and cleanup after name reuse.
Directory values can retain stopped references.Keep membership explicit, clear actor work and state at termination, and show replacement by remove/add.

Migration plan

The feature is additive. Existing imports and mediator behavior stay valid. Land the spike first, then complete each story with its tests and runnable docs. Do not cut a release as part of this change. The owner-approved release workflow will publish actors with the other libraries at the shared version.
