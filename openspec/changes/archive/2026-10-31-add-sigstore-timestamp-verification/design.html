Context

See proposal.md. The requirements are in sigstore-signed-timestamps and the deltas for bundle verification, trusted root and identity policy. The research read sigstore-go be417d9 (the same as v1.3.0, which gh pins), timestamp-authority cc4f1ac, digitorus/timestamp b4b58b9, digitorus/pkcs7 d678ea5, cli/cli 9490d20, in-toto/attestation 50bf017 and sigstore-conformance acb38c9. Where this design is stricter than sigstore-go, it says so.

Goals and non-goals

Goals: verify the three kinds above with the same verdicts as gh attestation verify and gh release verify-asset; keep one pure, synchronous verify call; let one combined root serve all GitHub attestations.

Non-goals: the proposal's out-of-scope list, BER input, and timestamp signatures other than ECDSA.

Research findings

RFC 3161 as sigstore-go verifies it

  1. signedTimestamp is a whole TimeStampResp: SEQUENCE { PKIStatusInfo, ContentInfo }. Status must be 0 (granted); trailing bytes fail. At most 32 timestamps.
  2. The ContentInfo is id-signedData with exactly one signerInfo, identified by issuer and serial number. sigstore-go does not check that the content type is id-ct-TSTInfo.
  3. TSTInfo: version, policy, messageImprint, serialNumber, genTime (GeneralizedTime, optional fraction), accuracy, ordering, nonce, tsa, extensions. Only genTime is the time; the imprint hash is SHA-256, SHA-384 or SHA-512, and must not be empty.
  4. Signed attributes: messageDigest equals the hash of the TSTInfo bytes; signingTime, when present, is inside the signer validity. pkcs7 does not check contentType or the ESS signing certificate. The signature covers the attributes re-encoded as a DER SET (tag 0x31 instead of [0]).
  5. The signature hash comes from an ecdsa-with-SHA* OID. GitHub signs with SHA-384 on P-384; the public-good TSA signs with SHA-256 on P-384.
  6. The trusted-root TSA chain is leaf first. When it has a leaf, the signer must equal it; embedded certificates go only into the intermediate pool. The chain is checked at genTime; the leaf EKU is critical and is exactly timeStamping; an intermediate has no EKU, timeStamping or any EKU.
  7. The imprint is the hash of the signature bytes: the DSSE signatures[0].sig or the message signature. Checked on the release bundle: SHA-256 of the signature is e381bcd6…2ac8, the imprint.
  8. The TSA validFor contains genTime, both bounds inclusive. sigstore-go does not compare genTime with "now".
  9. Failing timestamps are dropped; the threshold counts the rest, once for each TSA URI.

How gh combines time sources

gh picks the instance from the leaf issuer O=: public good gets SCT(1) + TransparencyLog(1) + ObserverTimestamps(1); GitHub gets SignedTimestamps(1) only, with no log and no SCT. The leaf chain must verify at every verified time. GitHub's root has no CT logs, and its leaves have no SCT.

Decisions

TSA-1. A strict internal timestamp package

Call. Add internal/timestamp over the existing DER reader. It reads DER only (no BER), and it is stricter than sigstore-go in three places: the encapsulated content type must be id-ct-TSTInfo, the contentType attribute must be present with that value, and a signingCertificateV2 hash, when present, must equal the hash (SHA-256 by default) of the signer that the attribute names. All real tokens pass these rules. A token without signed attributes fails, as RFC 3161 requires them. GeneralizedTime with a fraction is read for genTime (no trailing zeros, Z only).

TSA-2. Signer and chain

Call. For each TSA of the trusted root whose validity holds genTime: when its chain has a leaf, the signer is that leaf (an embedded certificate can never replace it); else the signer is the embedded certificate with the signerInfo's issuer and serial, and it must chain to the authority. The path is checked at genTime with the same validity, CA and critical-extension rules as Fulcio paths. The leaf EKU must be critical and hold only timeStamping; key usage, when present, must allow digitalSignature or contentCommitment. ECDSA P-256 and P-384 with SHA-256, SHA-384 or SHA-512 (from the signature OID) are supported; an RSA TSA gives Unsupported(TimestampAlgorithm(...)). The chain is checked before the signer key is read, so an embedded certificate that does not chain gives an invalid verdict, not a not-supported one.

TIME-2. Every time source must verify

Owner, approved 2026-10-31. The verified times are each log entry's integrated time and each timestamp's genTime. A timestamp or entry that does not verify fails the verdict, and genTime must not be later than "now". sigstore-go instead drops a failing timestamp when another time source meets its threshold. The strict rule is simpler to explain and cannot hide an attack in an extra timestamp; it can refuse a bundle that gh accepts only when the bundle holds a broken extra timestamp, which GitHub does not make.

ROOT-1. The SCT rule follows the root that issued the leaf

Owner, approved 2026-10-31. TrustedRoot::combine(roots) keeps, for each certificate authority, whether its source root lists CT logs. The SCT check runs only for authorities whose root lists CT logs. TrustedRoot::github_attestations() is the combination of the public-good and GitHub roots, so one root verifies public, private-repository and release attestations, and a public-good leaf still needs its SCT. This follows gh's instance choice, but by the authority that actually issued the leaf, not by the issuer O= text. Alternatives: an SCT rule by root only (a combined root would then require SCTs from GitHub leaves); or a list of roots in verify (a larger API change).

After the pre-merge review (2026-10-31): each log and authority keeps the position of its source root. A root that lists transparency logs also requires a verified entry from one of its logs, because gh requires a log entry for public good and a public TSA timestamp alone would hide a signature from log monitors. Every authority that issues the leaf counts, so the order of combined roots cannot weaken either rule, and an SCT must come from a CT log of the same root as its issuing authority.

ROOT-2. Pin GitHub's root from its TUF target

Call. Store the content-addressed TUF target bytes as testdata/github/trusted_root.json, list it in SHA256SUMS, and let generate-sigstore-assets.mbtx write TrustedRoot::github(). A test checks the digest 484cdfe1…fbb7. A TUF client stays a later change.

POL-2. Release policy

Call. Policy::github_release(repository, tag~) requires the SAN https://dotcom.releases.github.com, no issuer (the policy's issuer becomes optional inside Policy), predicate type …/release/v0.2 (a new PredicateType::github_release_v0_2()), and the predicate repository (ASCII case ignored), tag (exact) and purl (pkg:github/<owner>/<repo>@<tag>). .repository_id(...) and .owner_id(...) pin the predicate IDs. A new PolicyMismatch::ReleaseMismatch(field~, expected~, actual~) names the field. The artifact digest is the SHA-256 of a release asset; the tag commit (SHA-1) is out of scope. Statement keeps the predicate JSON for this check; Statement::predicate() gives a copy, so a verified result stays immutable. After review: a release policy also requires a certificate with no OIDC issuer (every workflow certificate has one), and workflow claims added to a release policy fail instead of being ignored. The purl version is percent-decoded and split after pkg:github/<owner>/<repo>@. Subjects with a uri and no name already parse.

LOG-2. Rekor v1 in-toto entries

Call, kept by the owner on 2026-10-31. Accept intoto/0.0.2 bodies: one envelope signature equal to the bundle signature, its PEM verifier equal to the leaf, and payloadHash equal to SHA-256 of the payload. This is small and makes six conformance cases (two of them with a TSA) test real behavior instead of a not-supported reason. Drop this group if you want the smallest change.

API-3. Verified times in the result

Call. VerifiedBundle replaces log_id, log_index and integrated_time with times : Array[VerifiedTime], where VerifiedTime has a time and a source: Log(log_id~, log_index~) or Authority(uri~). A bundle can now have no log entry, so the old fields cannot stay. New Failure cases: Timestamp(String), TimestampAuthority(String) and TimestampTime(time~, now~). Feature::TimestampAuthority is removed.

STR-1. Two strictness fixes

Call. An empty SCT list fails when an SCT is required. PrintableString accepts only A–Z a–z 0–9 space ' ( ) + , - . / : = ?; IA5String only bytes below 0x80.

Migration plan

Callers that read log_id, log_index or integrated_time read times instead. Callers that match every Failure or PolicyMismatch case add the new arms, and drop Feature::TimestampAuthority. The next release, with owner approval, carries the change.

Open questions

  • Whether to add a fresh private-repository attestation from a moonrockz private repository as a fixture. It does not change the design.
  • Data-residency roots (<domain>.trusted_root.json) and SANs (<domain>.releases.github.com), for GitHub Enterprise Cloud with data residency.
