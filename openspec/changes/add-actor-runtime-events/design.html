Context

See proposal.md for the motivation. The actors module of add-typed-actors (archived 2026-10-29, released in 0.8.0) has scope, Topic[M] with Scope::subscribe, Subject[M], ActorStatus with ActorEnd, and Admission (Accepted, Full, Closed). Topic::publish waits for admission to each subscriber. The mailbox already runs a discard action for each queued message when stop, cancellation or failure clears it. close returns the queued messages in a Pending[M] snapshot.

The module imports only core and moonbitlang/async 0.22.5, and scripts/validate-packages.mbtx enforces that list. moonrockz/moon-lander-config already imports moonrockz/ion@0.6.0. In that version, moonrockz/ion/ion has pub(open) trait ToIon { fn to_ion(Self) -> Ion } and impl ToIon for Json; it has no decode trait. MoonBit cannot derive ToIon and has no blanket implementations.

Labels identify the source of a decision. Owner means the user requested it. Call means this proposal chooses it for review.

Goals and non-goals

Goals: the useful part of the Akka and Pekko EventStream, which is runtime visibility of dead letters and lifecycle, as typed values on an explicit channel. The runtime must never wait for, or fail because of, an observer. A scope without a channel must cost nothing.

Non-goals: the items under "Out of scope" in the proposal, a second application pub/sub type next to Topic[M], and any change to the behavior of existing calls.

Decisions

EVT-1. An explicit channel for each scope, not a global bus (Owner: the channel, 2026-10-30; Call: the API)

RuntimeEvents::new() makes a channel. @actors.scope(events~, body) gives it to a scope. The child scopes of actors in that scope use the same channel. A separate top-level scope call uses only the channel that its caller gives, because scope has no implicit parent. To get one stream for a whole application, the application gives the same value to each top-level scope. That is the Akka system-wide stream, but as an explicit value.

async test "a dead letter after the actor ends" {
  let events = @actors.RuntimeEvents::new()
  @actors.scope(events~) <| scope => {
    let probe = @aqueue.Queue::new()
    let _ = events.subscribe(scope, @actors.Subject::from_queue(probe))
    let counter = scope.start(0, handle_counter, payload=@actors.PayloadPolicy::json())
    counter.close() |> ignore
    ignore(counter.to_ref().try_send(Increment))
    // probe: Started, then Undelivered(Closed, payload=Some(..)),
    // and Ended(MailboxClosed) when the actor finishes
    ...
  }
}

Alternative: one process-global stream, as in Akka. Rejected because it is mutable public state, and because the framework rules exclude global lookup. Alternative: a channel on each actor. Rejected because a dead-letter observer would then need the list of all actors.

EVT-2. A separate channel type with no public publish (Call)

RuntimeEvents is not a Topic[ActorEvent]. It has subscribe, close and subscriber_count, but no publish. Only the runtime publishes, so a subscriber can trust that each event came from the runtime. The internal publish uses try_send (EVT-4), which Topic::publish cannot do.

Alternative: reuse Topic[ActorEvent]. Rejected because application code could publish false runtime events, and because Topic::publish waits for admission, which would let a slow observer stop the runtime.

EVT-3. A small typed event set (Owner: dead letters and lifecycle, 2026-10-30; Call: the cases)

pub enum ActorEvent {
  Started(ActorAddress)
  Ended(ActorAddress, ActorEnd)
  Undelivered(ActorAddress, Undelivered, payload~ : @ion.Ion?)
}

pub enum Undelivered {
  Full       // try_send or reenqueue was rejected
  Closed     // send or try_send to a closing or ended actor
  Discarded  // queued work cleared by stop, cancellation or failure
}

Ended reuses ActorEnd, so it matches status(). The actor name is available through ActorAddress::name(), so the events do not repeat it. A failed initializer publishes neither Started nor Ended, because no handle was returned and the creator already gets the error.

Messages in the Pending snapshot of close are not dead letters: close gives them to its caller. Discarded asks already wake their callers; their Discarded event is also published, because the message was not processed. A reply to an expired Reply and a send to a custom Subject have no actor address, so they are out of scope.

Alternative: an open set of classes, as in Akka (DeadLetter, Dropped, UnhandledMessage). Rejected because MoonBit has no class hierarchy for subscription by type, and a closed enum lets subscribers match all cases. There is no "unhandled" case: a Receive value handles each message that it selects, and non-matches stay queued.

EVT-4. Non-waiting delivery: drop and count (Owner: non-waiting, 2026-10-30; Call: drop and count)

The runtime publishes with try_send to a snapshot of subscriptions, in subscription order. On Full it drops the event for that subscriber and adds one to EventSubscription::dropped_count(), a snapshot Int like queued_count(). On Closed it removes the subscription. The runtime never publishes an event about the delivery of a runtime event, so an observer that is full cannot cause more events.

This drop does not break the "no silent drop" rule of the actors spec. That rule is about mailbox policies. Here the runtime chooses not to admit an event, the subscriber's mailbox drops nothing, and the count makes each drop visible.

Alternative: wait for admission, as Topic does. Rejected because a dead letter could then block a sender, and an observer actor in the same scope could cause a deadlock. Alternative: a Lagged(count) event at the next admission. Not chosen because it needs one more mailbox slot at the moment the subscriber is already full; the owner can still choose it.

EVT-5. Subscriptions belong to the subscriber's scope (Call)

events.subscribe(scope, subject) -> EventSubscription raise ActorError binds the subscription to the subscriber's scope, as Scope::subscribe does for topics. It ends on unsubscribe or at that scope's exit. RuntimeEvents::close ends all subscriptions, rejects later ones with ActorError::TopicClosed, and stops all later publication. A closed channel does not fail the scopes that use it.

PAY-1. Ion as the payload format (Owner, 2026-10-30)

Payloads are @ion.Ion values from moonrockz/ion/ion. Ion is a superset of JSON and has decimals, timestamps, symbols, blobs and annotations, so a protocol keeps its value types in the payload. The payload type is concrete because one scope-level enum cannot hold the different protocol types M of its actors.

Alternative: core Json, which logging uses for properties. Rejected by the owner: it loses Ion types. A bridge to logging converts with @ion/json.to_json (LOG-1).

PAY-2. A payload policy for each actor, with a JSON bridge (Owner: the JSON bridge, 2026-10-30; Call: the forms and the default)

MoonBit has no specialization and no runtime type test, so the runtime cannot find out whether M has ToIon. The bound goes on the call that starts the actor, through a value in the portable root:

pub struct PayloadPolicy[M] { priv encode : ((M) -> @ion.Ion)? }

pub fn[M] PayloadPolicy::omit() -> PayloadPolicy[M]                   // the default
pub fn[M : @ion.ToIon] PayloadPolicy::ion() -> PayloadPolicy[M]       // Ion-native codec
pub fn[M : ToJson] PayloadPolicy::json() -> PayloadPolicy[M]          // @ion.Ion(m.to_json())
pub fn[M] PayloadPolicy::encode(f : (M) -> @ion.Ion) -> PayloadPolicy[M] // custom or redacted

start, start_with, spawn and respond (for Req) get an optional payload? argument. create does not, because service messages are closures. Because ToIon cannot be derived, the JSON bridge is the common path: a protocol with derive(ToJson) gets a payload with no other code. A protocol that carries a Reply[R] cannot derive ToJson; encode lets it encode only its data fields.

The default is omit, because a message can hold a secret and an event usually goes to a log. The ion and json forms write the whole message; the documentation says so and shows encode for redaction. The encoder type cannot raise, so encoding cannot fail a delivery.

Alternative: require ToIon on every protocol. Rejected because protocols with replies or closures could then not be actors. Alternative: a lazy payload thunk. Rejected because it keeps the message alive in the event and is not data.

PAY-3. Encode only when someone listens, and isolate each payload (Call)

The runtime calls the encoder only for an Undelivered event and only when the channel has at least one subscription at that moment. A loop of rejected try_send calls with no observer does no encoding work. Ion values hold MoonBit arrays, which can change, so each subscriber gets its own value: the runtime encodes once and gives each later subscriber a deep copy. Logging uses the same copy rule for its JSON properties.

DEP-1. Actors imports the Ion data model (Owner: Ion, 2026-10-30; Call: the limits)

pkgs/actors/moon.mod imports moonrockz/ion@0.6.0, the version that config already uses, so the workspace resolves one Ion version. Actors packages import only moonrockz/ion/ion, not the text, binary, schema or JSON packages. scripts/validate-packages.mbtx adds moonrockz/ion to the external limit for actors and gets a package-level check for that rule. The Ion data-model package builds on all four targets, so the portable root stays portable. The decode work in the separate moonrockz/ion workspace is not a dependency; a later version bump can take it.

Alternative: put payloads in an optional actors-ion package. Rejected because ActorEvent must name the payload type, so the runtime needs it in any case.

LOG-1. A logging bridge as an example, not a dependency (Call)

Logging imports only core, and actors does not import logging. A bridge is an ordinary actor in application code: it subscribes to the channel, converts the payload with @ion/json.to_json, and writes a LogEvent property. When the conversion fails, it writes the Ion text form as a string property. The unpublished acceptance tests hold this example, so no published module gets the dependency.

Risks and trade-offs

RiskMitigation
Event publication adds work to each send, start and end.A scope without a channel checks one optional value and does nothing else. Compare the local actor benchmark with and without a channel; benchmarks stay a manual task.
A payload writes a secret into a log.The default is omit; ion and json are explicit; the documentation shows encode for redaction.
Dropped events hide a problem.Each subscription counts its drops; tests use a mailbox large enough for their events, or an unbounded one.
A subscriber actor in the same scope observes its own end.Its own Ended event finds a closed mailbox and is dropped from the subscription with no feedback event (EVT-4).
The Ion dependency adds moonbitlang/x packages to actor consumers.Config already resolves the same graph. The candidate consumer gate checks the actors archive on all its targets.
Deep copies of large payloads cost memory when there are many subscribers.Encoding happens only for undelivered messages with subscribers; most applications have one or two observers.

Migration plan

Additive. Existing calls keep their behavior, because events and payload are optional. No release is part of this change; a separate owner-approved release PR publishes it.

Open questions

Whether the receive test runner should also record runtime events, so that a unit test can assert them with no scope. This can be decided in group 2 without a change to the specs.
