Report host completion

Issue #130. See proposal.md.

Context | Goals | Decisions | Risks | Migration

Context

A pending signal can end hosting.run before any hook. Console already receives the complete typed outcome and owns the process exit boundary. The logging bridge reserves its finalizer to drain the session.

Goals and non-goals

Let the application report a returned outcome once without a service or command callback. Preserve defaults and embedded execution. Do not add application schemas, fake outcomes for factory exceptions or an event loop.

Decisions

API-1. Add completed (Call)

Console exports Completion as an async function from RunOutcome and ExitCode to Unit. Console.run and both bridge methods accept completed. Lambdas need no new construction or registration.

ORDER-1. Finalize before reporting (Call)

Run host cleanup and failure reports, select the code, run the existing finalizer, then invoke completed. The bridge finalizer closes diagnostics even when no service started. The callback sees the actual outcome and selected code after sink failures. An earlier hosted close remains idempotent and keeps diagnostic-before-telemetry order.

FAIL-1. Reuse exit precedence (Call)

Protect reporting from cancellation. Catch callback errors once: success becomes failure; a selected nonzero code remains. Poll the retained signal source after reporting so a late signal still wins. The selected code is a snapshot at callback entry; later callback failure or signal can change process exit. Applications own the callback time budget and output bytes.

SCOPE-1. Report returned outcomes (Call)

Configuration and lifecycle failures returned as RunOutcome are included. A factory or signal-setup exception before hosting.run returns has no outcome and keeps the existing raising cleanup path. Do not construct a false outcome.

Risks and trade-offs

A reporter can raise after writing partial output or can wait indefinitely. The application owns its output and time budget. Test actual native/Node/Bun child exit and stdout, pending/startup/running stops, callback failure, existing closed sessions and cancellation protection. Keep the old no-callback cases.

Migration plan

Add completed=(outcome, selected) => ... to either bridge entry point. Publish a later shared patch only through release.yml after green review and CI. Verify actual approved archives and fresh native/JS public consumers, then send proof to the coordinator. No downstream edits.
