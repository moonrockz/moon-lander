Context

See proposal.md for the reason. The repository pins one primary MoonBit toolchain in .config/mise/config.toml. Before this change, check:moonx and check:moonx-stock16 installed stock 0.10.17+d971670cd and 0.10.16+b1a0e846e as task-scoped tools and qualified a copied Moonx module with each one. scripts/check-moonx.mbtx identifies a stock toolchain by its moonc version and the commit of moon and moonrun.

Goals and non-goals

Goals: one Moonx source that the pinned formatter, --deny-warn and the qualification all accept, with the same evidence kinds as before.

Non-goals: a qualification matrix of several stock toolchains; changes to the launcher API or to the frozen upstream inputs.

Decisions

STOCK-1. Qualify the stock toolchain of the primary pin (Owner)

The owner chose this on 2026-11-07. check:moonx runs qualify-moonx-stock.mbtx 0.10.20+65efd5b93. The script still completes the installation with the official installer when its core or moonx is missing, so the qualified toolchain stays a stock installation, not a source build. The identity check accepts moonc v0.10.20+65efd5b93 with moon and moonrun at commit 940aa18, and refuses every other identity.

Alternatives: keep pkgs/moonx on the old syntax with a warnings override and a formatter exclusion (rejected: a deprecated syntax, a second formatter for the frozen runtime and an exception in every lint path); hand-written trait implementations instead of derives (rejected: it changes frozen upstream files and ToJson moved to moonbitlang/core/json in 0.10.20, so the same source still differs between the toolchains).

STOCK-2. The stock pin follows the primary pin (Call)

A later MoonBit upgrade changes the primary pin, the StockPin and StockVersion values and the spec scenario together. There is no separate stock pin to keep in step.

STOCK-3. Regenerate the frozen runtime with the pinned formatter (Call)

mise run moonx-runtime:generate formats the reconstructed files with the pinned moon fmt. The upstream digests in provenance.json do not change; only the generated digests change.

Risks and trade-offs

RiskMitigation
Consumers on stock 0.10.16 or 0.10.17 cannot use the next Moonx release.Published 0.11.0 stays on the registry. The release notes mark the change as breaking.
The Windows Ctrl-C to Ctrl-Break behavior of Moonrun 940aa18 can differ from 2284bd2 and 3778465.The Windows CI job runs check:moonx on the new stock. A difference that needs Windows work goes to its own bead.

Migration plan

Land with the MoonBit 0.10.20 upgrade. To roll back, revert that pull request; the stock 0.10.16 and 0.10.17 tasks and the old frozen digests come back with it.
