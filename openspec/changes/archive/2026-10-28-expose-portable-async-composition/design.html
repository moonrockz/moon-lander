Expose portable async composition

Context

See proposal.md. The old package-wide target declaration prevents planning before target-gated uses can be removed. The pinned compiler accepts basic async composition on wasm-gc after that declaration is removed. The embedded driver already runs async hooks until completion or first suspension.

Goals and non-goals

Keep one sender and middleware implementation and the existing import path. Do not start an embedded scheduler, replace a real async send with a synchronous send, or change timeout and topic behavior on their current targets.

Decisions

PKG-1. Remove the package-wide restriction (Call)

Expose Sender, middleware, before, after, finally_ and synchronous-sender wrapping through the existing mediator/async package on all four targets. A second composition namespace would add migration and type bridging without a need. Keep the same implementation and opaque types.

RUN-1. Gate runtime operations by file (Call)

Move timeout to timeout.runtime.mbt. Gate that file and Topic operations to wasm/js/native. Keep old event-loop tests and README async tests on those targets. The build system cannot condition imports, so explain a narrow unused-import warning exception for wasm-gc. This follows the existing hosting package boundary. Do not implement a wasm-gc timeout or concurrent scheduler.

EMB-1. Use the existing embedded driver (Owner)

A non-suspending handler and middleware complete under hosting.run_embedded. Actual suspension remains that driver's typed failure. Native and JS handlers must really await completion; tests cover a JS Promise, success, failure, cancellation and finalization around the real handler. No downstream dispatcher is copied.

Risks and trade-offs

RiskMitigation
Users infer an embedded event loopDocument operation-specific target support and verify suspension is still rejected.
Runtime exports or timeout behavior regressRun all existing async tests on three targets and explicit native/JS timeout compatibility cases.
A zero-test wasm-gc leg looks greenAdd a required nonzero portable acceptance leg on every target.

Migration plan

No source change for existing async imports. Embedded callers use the same typed async sender inside run_embedded. Finish the running 0.7.1 publication and proof first, then publish a later owner-authorized patch through release.yml. Qualify fresh public consumers and approved archive checksums; do not overwrite versions or tags.
