Context

See proposal.md. The console driver already owns probe retention and protected finalization. Runtime Session already owns idempotent, protected close. The bridge omits both composition points.

Goals and non-goals

Reuse those two implementations. Add no second lifecycle or signal owner. See requirements and tasks.

Decisions

SIG-1. Forward the probe (Owner)

Both bridge entries accept optional signals and pass the same probe to console.run. Do not add a bridge latch, listener or fabricated reason. The driver retains consuming observations; the enclosing owner controls escalation.

SES-1. Expose the existing session (Call)

Add run_with_session(settings, host, command, observer?, signals?). Its factory takes the existing opaque runtime Session. Existing run delegates and supplies session.logger() to its old factory. A new context wrapper would duplicate existing methods. Adding a second callback to run would complicate a simple default path.

SES-2. Keep finalization unconditional (Owner)

A diagnostic service calls session.close() in its real stop hook. A previous telemetry service then stops after that close. Close ends admission; only records accepted before it are covered. Later hook or stopped-event log attempts do not reopen the session. The unchanged bridge finalizer calls close again, reads the same report and writes failures directly to standard error. The outer with_session also closes after an exception or cancellation.

Risks and trade-offs

RiskMitigation
Telemetry tries to log after diagnostic closeDocument the admission boundary; retain direct default failure diagnostics.
Host deadline skips or cancels a stop hookKeep unconditional protected finalization and verify it with real child processes.
A consuming reader loses signal identityUse the existing console latch and test real parent signals with a worker that does not yield.

Migration plan

Publish shared 0.7.1 through release.yml after green checks and reviewed merge. Existing callers need no source changes. Session-aware callers opt in. Roll back consumption to 0.7.0 if needed; never replace registry archives or tags. Qualify all nine public archives with approved checksums and fresh consumers.
